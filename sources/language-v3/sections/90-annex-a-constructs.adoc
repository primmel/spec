[[annex-a-constructs]]
== Annex A (normative): The construct registry

This annex is the registry of every top-level construct of the language.
It reproduces the parser configuration of the reference implementation
(`packages/primmel/src/ser-des/config/index.ts` of primmel-ts); the two
are verified together, and a discrepancy is a defect in one of them.

The annex is generated from the parser configuration by the parity
tooling of the kernel repository (`packages/primmel/scripts/annex-a.mts`
of primmel-ts, `--check` in continuous integration); it is never
hand-edited, and a hand edit is a defect in this annex.

During the reconfiguration whose plan of record is the Primmel
reconfiguration roadmap, a construction freeze applies to the parser:
no new construct joins the parser configuration. A construct lands
only together with the specification section this annex points at, in
one change, with the parity check green in both repositories'
continuous integration; the unregistered constructs carry their
triage dispositions in the kernel's visible `registry-triage.prl`
list, and the list only shrinks.

Every construct declaration has the shape `KEYWORD IDENTIFIER { ... }`:
one keyword, one identifier, one block payload
(<<top-level-shape,9.1>>). The four special declarations of the first
table are the exceptions. The "since" column states the language
generation that introduced the construct: v2 (the MN 113 generation,
including its extension wave), v3 (this document's first revision),
v3.1 (the 2026-08-28 revision's extension set,
<<dataspaces-policies-trust,clause 19>>), or v3.2 (the 2026-09-04
revision's consumption extension set, primmel/spec#18); v3 accepts every
v2 construct
(<<annex-d-lineage,Annex D>>), v3.1 changes no v3 construct, and v3.2
changes no v3.1 construct.

=== Registry notes

. `variable` and `measurement` feed the same collection; `measurement` is
the canonical keyword of the MN 113 text and `variable` the legacy
spelling. Both remain registered.
. The event constructs register under both the short and the full keyword
forms; the two forms of one event kind share one parser.
. `canvas` is the diagram container; `subprocess` is its v2 spelling. A
process's `subprocess` facet (<<process-subject,12.1>>) names the page it
renders on; the two uses of the word are one reference.
. `view` is the legacy spelling of `view_profile`.
. The include directive (<<include-directive,16.2>>) is a preprocessor
directive, not a construct; it never reaches the parser.
. The checker allowlist file `.primmel-allowlist.prl` is package metadata
(<<allowlist,17.4>>), not content; it is excluded from the package merge.
